# Finder opening regression — 2026-10-08

Version 0.8.1, build 24.

Finder requests now go through the application delegate rather than a SwiftUI
`onOpenURL` scene handler. This avoids combining SwiftUI's automatic event window
with a window requested by the document registry. Cold-launch requests wait for
the initial scene; subsequent queued files request one scene at a time.

Native testing also reproduced a separate reopening failure: a workspace retained
after its window closed was still treated as an open document. The window delegate
now removes closed windows and their workspaces from the registry. Window lookup
uses all registered windows, including nonselected tabs.

Verification uses an isolated app bundle and synthetic PDFs. It covers cold opening,
opening a second document while running, reopening an existing tab, opening two
files together, explicit Command-T, filling the resulting welcome tab, and reopening
a closed document. OpenAndLinkSmoke includes a real NSWindow close with a retained
workspace, plus cold-launch and queued-request regressions. SessionCloseSmoke
checks deliberate close and termination/recovery behavior.

Reproduce automated checks with:

```sh
./scripts/run-tests.sh OpenAndLinkSmoke SessionCloseSmoke
./build-app.sh
```
