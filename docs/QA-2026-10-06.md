# zzPDF 0.8.0 review — October 6, 2026

Reviewed the features and implementation at `9e1e7c7`, then updated the welcome
screen, replaced the app icon, and corrected the issues below. Source, UI copy,
and documentation remain in English.

## Findings and fixes

| Finding | Reproduction / evidence | Resolution |
| --- | --- | --- |
| Failed redaction rendering could still produce an exported PDF containing the covered text. | A redacted page with a crop box too small to render returned a partially processed document. The caller also treated failure like a document without redactions. | Abort the entire flattened export when any redacted page cannot be rendered. Both normal and password-protected flattened exports use the same check. Regression tests verify that failure leaves an existing destination untouched and that a valid export removes searchable text. |
| Undo/redo moved annotations on cropped pages after text replacement. | Move a note from a page with crop origin `(30, 40)` to the rewritten page and back, repeated three times. Its coordinates drifted. | Translate by the difference between source and destination crop origins in both directions. |
| Consecutive PDF text-show operators could remove or reposition unrelated text. | A stream with `(EDIT) Tj ( KEEP) Tj` and no explicit repositioning lost both operands although the rectangle covered only the first origin. | Detect unsupported implicit cursor advances and preserve the complete stream, using the existing visual-cover fallback. This avoids guessing glyph widths. |
| Document comparison performed every page render and pixel comparison on the main actor. | Inspection of the comparison task showed synchronous rendering on the UI thread. | Compare serialized snapshots in a background task using independent PDFKit documents, and ignore results if the active comparison/document changed. Tested matching and invalid snapshots. No large-document performance benchmark was performed. |
| Command-F could not focus Search at minimum window width. | Native UI test: the search field was hidden in toolbar overflow; Command-F opened the sidebar but typing did not enter a query. | Replace the toolbar field with a Find button and put the field inside the search sidebar. Also handle Command-F when the sidebar starts hidden. Automated hosting-window checks and native keyboard checks pass. |

Also removed an actor-isolation warning in registry initialization and corrected
the test runner to retain the first failed execution's stdout/stderr instead of
rerunning a failed test and potentially losing the original evidence.

## Welcome and artwork

The welcome screen now introduces six groups: Edit text, Annotate & draw, Fill &
sign, Organize pages, Search & compare, and Finish & share. It explicitly mentions
existing-text editing, OCR, comparison, watermarks, and page numbering. The content
scrolls when recent documents or a smaller window need more room.

The new indigo document-and-nib icon is shared by the app bundle and welcome screen.
All ten macOS icon representations were regenerated. The transparent master,
generation prompt, and reproducible icon conversion script are included in the
repository: `AppResources/IconDesign.md` and `scripts/build-icon.sh`.

## Automated verification

The complete suite of 22 programs passed after the document fixes. After the final
search UI change, SearchVisibilitySmoke, SearchNavigationSmoke, and SearchOptionsSmoke
were compiled and passed. This is **23 distinct passing suites**, with the two
existing search suites rerun after the final change.

Coverage includes:

- AutoFillSmoke, FormOverlaySmoke: form detection, filling, free text, shape appearance.
- ContentStreamSmoke, PageFontSmoke, TextEditSmoke: stream parsing, fonts, in-place editing, cancellation, undo and redo.
- DrawingToolsSmoke, InkResizeSmoke: lines, arrows, polygons, ink resizing and export.
- OCRSearchableSmoke: scanned-page OCR and searchable text layers.
- OpenAndLinkSmoke, SessionCloseSmoke, RecoverySmoke, ReadingAndAutosaveSmoke: open routing, tabs/windows, deliberate close, recovery, autosave during editing, reading modes.
- PageSelectionSmoke, PageStampSmoke: multi-page operations, annotations, stamps and watermarks.
- DocumentToolsSmoke: comparison, form-data round trips, signature detection.
- SearchNavigationSmoke, SearchOptionsSmoke, SearchVisibilitySmoke: result navigation, filters and keyboard focus with a hidden sidebar or a 980-point window.
- PrintSmoke, SettingsSmoke, UndoSmoke: print-operation creation, preferences and undo history.
- ReviewRegressionSmoke: failed redaction export, destination preservation, cropped annotation round trips, unsupported text advances and background comparison.

Local logs: `work/review-full-suite.log`, `work/review-search.log` and per-suite
logs in `work/tests/`. These generated files are not committed.

Reproduce with:

```sh
./scripts/run-tests.sh
./build-app.sh
codesign --verify --deep --strict outputs/zzPDF.app
unzip -t outputs/zzPDF-macOS.zip
```

## Build and limits

Version 0.8.0, build 23, Apple Silicon. App signature, bundle property list, archive
integrity and whitespace checks passed. The build used the existing direct-compiler
fallback after Swift Package Manager could not resolve the installed SwiftUI macro
plugin. The source compiles with the selected compiler/SDK; the SDK still warns
about the older file-drop API. The package is ad-hoc signed, not notarized.

These checks cover the supplied fixtures and the tested local macOS environment;
they are not a guarantee for every PDF producer, embedded font or document size.
Text editing remains line/block replacement, with a visual fallback for unsupported
streams and no document-wide reflow. Such fallback can leave original text in the
file, so it must not be used as redaction. Digital signatures are detected, not
cryptographically validated. Physical printing and other macOS versions were not tested.
